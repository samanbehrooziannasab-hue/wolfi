# 🐺 ابر پرامپت — ادامه‌ی پروژه‌ی Trading Wolf AI

> این پرامپت را کامل به agent بدهید تا در محیط جدید (اکانت Freebuff جدید / دپلوی
> Convex تمیز) پروژه را بشناسد، وضعیت را بداند و ادامه دهد.

---

## ۱) این پروژه چیست؟

یک سیستم کامل **Trading/Monitoring** با نام «Trading Wolf AI» (موتور خصوصی و
خودکار معاملات و پایش بازار، نسخه ۱.۳):

- **موتور معاملات خودکار**: اسکن چندجفت‌ارز و چندتایم‌فریم، ۱۰۰+ استراتژی
  (پرایس اکشن، SMC/ICT، روند، مومنتوم، الگوها…)، امتیازدهی ۱ تا ۱۰۰، گیت‌های
  ورود (امتیاز، اجماع، تأیید مستقل، RR، تازگی داده)، مدیریت ریسک ۵ سطحی
  (خیلی کم تا خیلی زیاد)، هدف پله‌ای زمانی (freqtrade ROI)، cooldown، حد ضرر
  شناور، بک‌تست و بهینه‌ساز پارامتر (hyperopt)، مناظره بول/بیر AI (TradingAgents)،
  لایه‌ی تحقیق بازار AI، باز کردن دستی معامله.
- **صرافی‌ها**: CCXT (binance/bybit/okx/bingx/bitget/kucoin/mexc/gate/… ۲۱ صرافی)
  + آداپتور بومی **نوبیتکس**؛ اتصال همزمان چند صرافی با سوییچ روشن/خاموش؛
  اجرای واقعی سفارش در حالت live و paper در حالت demo.
- **تلگرام**: ربات دو زبانه (fa/en)، ورود با تلگرام (Mini App + تأیید شماره +
  عضویت کانال)، **کانال فارسی + کانال انگلیسی** (اعلان‌ها و کارت‌های معامله به
  هر دو)، وبهوک، اعلان به مدیر، ارسال پیام به کاربر/کانال از پنل مدیریت.
- **AI**: چت مشاور برای کاربران + زنجیره‌ی ۶ پروایدری با **پایه‌ی رایگان بدون
  کلید (Pollinations)** + Gemini/Groq/OpenRouter/Cerebras/Mistral/Anthropic به‌عنوان
  مکمل؛ بک‌تست صحت‌سنجی AI.
- **اقتصاد داخلی**: سکه ولف، پیش‌بینی کندل، کوئیز، ووچر، رفرال، پلن‌های VIP
  (برنزی تا الماس با کارمزد و روزهای مختلف)، کیف پول (USDT/تومان)، برداشت و
  درخواست‌ها، تیکتینگ (با شناسه و چت)، اعلان‌ها (باقی‌ماندن ۲۴ ساعت).
- **پنل مدیریت**: تب‌های درختی، تب **اتصالات و کلیدها** (همه‌ی مقادیر قابل تزریق
  با رمزنگاری AES-256 در حالت ذخیره)، تب **مانیتورینگ سرور** (رانتایم، حافظه،
  سلامت سرویس‌ها، شمارش دیتابیس، کنترل موتور)، لاگ‌های فارسی، کاربران، کیف پول،
  صرافی‌ها، گزارش‌ها.
- **فرانت‌اند**: React + Vite + Tailwind + shadcn/ui + Framer Motion، فارسی/انگلیسی،
  RTL/LTR، تم تیره/روشن (گرافیت/زمرد/طلایی)، فونت Vazirmatn، موبایل‌فرست،
  سازگار با Telegram Mini App.

## ۲) وضعیت فعلی (تا کجا پیش رفتیم)

- **بک‌اند اجرایی فعلی روی Convex** (`src/convex/`) — کامل و کار می‌کرد؛
  در محیط قبلی دپلوی Convex به محدودیت پلن رایگان خورد و **غیرفعال شد**؛ به همین
  دلیل پروژه در محیط جدید (اکانت Freebuff جدید) ادامه پیدا می‌کند که دپلوی Convex
  تمیز و فعال دارد.
- **بک‌اند خود-میزبان** (`server/` — Node + Hono + PostgreSQL + Redis) از قبل کامل
  است (~۸۰ endpoint، موتور، صرافی‌ها، تلگرام، AI) + `deploy/` (docker-compose، PM2،
  nginx، env.example، backup/restore) + اسکریپت‌های `scripts/install.sh` (نصب روی
  سرور خام) و `scripts/update.sh` (بروزرسانی یک‌دستوری امن).
- **فرانت‌اند هنوز روی کلاینت Convex است** — مهاجرت به REST فازبندی شده
  (نقشه‌ی کامل در `docs/MIGRATE_FROM_CONVEX.md`).
- مستندات کامل در `docs/` (VPS_FA، DEPLOY، TELEGRAM، SECURITY، TRADING_ENGINE،
  BROKER_CCXT، FREQTRADE، TRADINGAGENTS، FREE_LLM، VIBE_TRADING، CONVEX_RESET).

## ۳) اولین قدم‌ها در محیط جدید (اجباری، به همین ترتیب)

1. `bun convex dev --once` — کدگن علیه دپلوی Convex جدید (باید سبز شود؛ اگر
   اعتبار سؤال داشت به کاربر بگویید کلید/URL را در تب Keys بگذارد).
2. `bun tsc -b --noEmit` — تایپ‌چک باید سبز شود؛ اگر خطا بود رفع کنید.
3. تست موتور: اجرای `evaluateStrategies` با کندل نمونه (مانند `scripts/engine-test.ts`).
4. به کاربر بگویید در تب Keys کلیدهای لازم را بگذارد (اختیاری: GEMINI/GROQ و…؛
   توکن تلگرام از `src/convex/constants.ts` seed می‌شود).
5. راه‌اندازی تلگرام: تب **اتصالات و کلیدها** ← توکن ربات + آیدی مدیر + شناسه
   کانال fa/en را وارد و ذخیره → «اتصال وبهوک» → «تست اتصال ربات».
6. پیش‌فرض‌ها: ورود مدیر `wolfadmin / Wolf3010!` (به کاربر بگویید عوض کند).

## ۴) کارهای باقی‌مانده (خواسته‌های اصلی کاربر)

1. **مهاجرت کامل از Convex** به بک‌اند خود-میزبان (`server/`) — طبق
   `docs/MIGRATE_FROM_CONVEX.md` فازبه‌فاز: (۱) auth روی REST، (۲) داشبورد کاربر،
   (۳) پنل مدیریت، (۴) موتور/بک‌تست/بروکر، (۵) سکه، (۶) حذف پکیج‌های convex.
2. **اجرای واقعی روی سرور شخصی** کاربر (آزمایش با `scripts/install.sh` روی VPS
   خام و سپس `scripts/update.sh` برای نسخه‌های بعدی).
3. هر بهبود/دیباگی که کاربر در تست سرور شخصی پیدا کند.

## ۵) قوانین کار (اجباری)

- اول همه‌ی فایل‌های مرتبط را کامل بخوان؛ معماری را بفهم؛ بعد تغییر بده.
- **هیچ قابلیت موجودی را بدون دلیل حذف نکن** و هیچ بخش مهمی را Placeholder/
  Demo/Fake تحویل نده. همه‌چیز باید واقعی و قابل اجرا باشد.
- اطلاعات/ID/توکن‌های TEST را در `src/convex/constants.ts` حفظ کن (همان مقادیر
  فعلی — فقط قابل تغییر از پنل).
- بعد از هر تغییر: `bun convex dev --once && bun tsc -b --noEmit` را اجرا کن و
  فقط وقتی سبز شد اعلام تمام کن.
- متن‌های فارسی: درست، بدون لحن رباتیک، بدون ادعای سود تضمینی. UI فارسی
  راست‌چین و RTL باشد.
- سرورهای dev را از ترمینال ری‌استارت نکن؛ فایل‌ها را با ابزارهای ویرایش فایل
  عوض کن (نه sed/اسکریپت شل)؛ `.env` را دست نزن (کلیدها از تب Keys).
- حذف Convex ممنوع تا وقتی مهاجرت REST کامل و سبز نشده (build نباید بشکند).

## ۶) نقشه‌ی فایل‌های مهم

```
src/convex/            → بک‌اند فعلی (Convex): engineWorker (موتور)، markets (فید)،
                         broker (CCXT+نوبیتکس)، settings (تنظیمات + رمزنگاری)،
                         telegram (ربات/وبهوک)، notify، aiChat، nodeCalls (AI)،
                         coins، admin، monitor، engineEval/Core، schema، constants
src/pages/             → Landing (صفحه اصلی)، Auth، Dashboard (پنل کاربر+مدیر)
src/hooks/             → use-wolf-auth (auth)
server/                → بک‌اند خود-میزبان (Hono+Postgres+Redis) — کامل
deploy/                → docker-compose، PM2، nginx، env.example، backup/restore
scripts/               → install.sh (نصب سرور خام)، update.sh (بروزرسانی امن)، engine-test.ts
docs/                  → همه‌ی مستندات + SUPER_PROMPT + MIGRATE_FROM_CONVEX
```
